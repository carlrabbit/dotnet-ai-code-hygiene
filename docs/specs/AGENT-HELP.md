# Agent Help Contract

The only supported command namespace is `dotnet hygiene`. The no-argument command is the ordinary agent entrypoint; `dotnet hygiene help --agent` provides stable CLI-owned workflow guidance without provider-specific prompting.

Guidance describes bootstrap and explicit external baseline approval, trusted gate selection, repository-wide SDK formatting and normalization, findings, selected-only grouped review work, independent rule questions and decisions, escalation, stale-work revalidation, reruns after remediation, terminal status semantics, practical manual diagnostics, release upgrades, and the fact that the CLI does not invoke a model/provider. Selected semantic work includes source-backed primary and related anchors with bounded evidence; unavailable or truncated necessary context is called out. Modernization verdicts are not durable approval: prefer the suggested syntax, retain only with a narrow justified source suppression, and leave uncertain work outstanding.

Bootstrap and profile-migration reports expose `reportSha256`. After reviewing the exact report, an authorized approver records the external assertion with `dotnet hygiene baseline accept --approver <identity> --report-sha256 <sha256>`. A profile marker alone never authorizes a gate, and stale reports/snapshots must be regenerated through `dotnet hygiene bootstrap` before acceptance.

Acceptance is a caller assertion that every fixed question passes and no escalation condition applies. Check rendering, expansion, and handoff do not consume review tickets. Modernization suggestions use occurrence-level `desirable`, `retain`, or `uncertain` decisions and are never applied by the CLI. Architecture questions escalate to the planner only for unresolved material contract, ownership, interface, or design decisions. Behavior questions escalate for a missing or conflicting business, security, or data-boundary policy; unsupported runtime context remains uncertain. Test, documentation, and comment questions escalate to the frontier for material uncertainty or an unestablished observable contract. Comment intent is contextual: legal, administrative, and ordinary comments remain eligible; a comment is not defective merely because it does not narrate implementation. The visual-block review candidate indicates an opportunity, does not mandate a blank line, and is not automatically rewritten.

For any of the 17 general semantic-review rules, negative or uncertain selected items use `dotnet hygiene review handoff <batch> --output json`, which writes a durable request and reports `escalation-required` with the designated reviewer class. The rules share a ten-obligation gate budget, with at most two context-affected obligations. The nine modernization families retain their separate shared five-package sample. Previous local modernization decisions remain migration state only and are never approval. Retired omnibus-rule acceptances are not transferred to new rules; preserve legacy state and follow the tool's explicit archival or removal guidance.

Manual diagnostics remain under `dotnet hygiene check`, `rules`, `explain`, `format`, `normalize`, and `review`. `--review-all` remains bounded. The separate `dotnet hygiene --yolo-all` operation is an exhaustive read-only audit: first show the explicit user-task question; proceed only with `--attest-explicit-task`, otherwise stop. Continue report collection with `dotnet hygiene audit next --run <audit-dir>`, submit only actual external judgments using `dotnet hygiene audit record --run <audit-dir> --file <judgments.json>`, and write JSON/Markdown reports with `dotnet hygiene audit finish --run <audit-dir>`. Report problems and uncertainty without fixing code, accepting normal reviews, escalating, formatting, bootstrapping, or updating the tool. Audit work orders embed source context; the selected local report destination is the caller's responsibility. Root and subcommand help accurately describe the installed command and lifecycle. There is no pre-1.0 compatibility obligation for the old bare `hygiene` command or former CLI layout.
