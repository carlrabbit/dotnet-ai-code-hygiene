# Agent Help Contract

The only supported command namespace is `dotnet hygiene`. The no-argument command is the ordinary agent entrypoint; `dotnet hygiene help --agent` provides stable CLI-owned workflow guidance without provider-specific prompting.

Guidance describes bootstrap and explicit external baseline approval, trusted gate selection, repository-wide deterministic formatting and normalization, findings, selected-only grouped review work, independent rule questions and acceptances, escalation, stale-work revalidation, reruns after remediation, terminal status semantics, practical manual diagnostics, release upgrades, and the fact that the CLI does not invoke a model/provider.

Bootstrap and profile-migration reports expose `reportSha256`. After reviewing the exact report, an authorized approver records the external assertion with `dotnet hygiene baseline accept --approver <identity> --report-sha256 <sha256>`. A profile marker alone never authorizes a gate, and stale reports/snapshots must be regenerated through `dotnet hygiene bootstrap` before acceptance.

Acceptance is a caller assertion that every fixed question passes and no escalation condition applies. Check rendering, expansion, and handoff do not consume review tickets. Negative or uncertain summary, test-quality, and comment-intent work goes to the frontier; BORINGness and type-responsibility concerns go to the planner. Comment intent is contextual: legal, administrative, and ordinary comments remain eligible; a comment is not defective merely because it does not narrate implementation. The visual-block review candidate indicates an opportunity, does not mandate a blank line, and is not automatically rewritten.

When the agent determines a selected item is negative or uncertain, `dotnet hygiene review handoff <batch> --output json` writes a durable request and reports `escalation-required` with the designated reviewer class. The handoff does not accept or consume the review items; the agent reruns the lifecycle after the reviewer decision or any source change.

Manual diagnostics remain under `dotnet hygiene check`, `rules`, `explain`, `format`, `normalize`, and `review`. `--review-all` remains bounded. The separate `dotnet hygiene --yolo-all` operation is an exhaustive read-only audit: first show the explicit user-task question; proceed only with `--attest-explicit-task`, otherwise stop. Continue report collection with `dotnet hygiene audit next --run <audit-dir>`, submit only actual external judgments using `dotnet hygiene audit record --run <audit-dir> --file <judgments.json>`, and write JSON/Markdown reports with `dotnet hygiene audit finish --run <audit-dir>`. Report problems and uncertainty without fixing code, accepting normal reviews, escalating, formatting, bootstrapping, or updating the tool. Audit work orders embed source context; the selected local report destination is the caller's responsibility. Root and subcommand help accurately describe the installed command and lifecycle. There is no pre-1.0 compatibility obligation for the old bare `hygiene` command or former CLI layout.
