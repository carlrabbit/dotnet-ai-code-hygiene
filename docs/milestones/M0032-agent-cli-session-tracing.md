## Goal and target capability

Deliver **one complete, independent, agent-operated local command-line tracing tool** in the .NET AI Workbench monorepo. An agent can enable it *inside an already-running chat* simply by invoking the CLI for the remainder of that chat, without hook registration, agent-runtime changes, service installation, or a different agent launcher. The tool records actual wrapped command executions, optional explicitly declared non-command activity, and session lifecycle; it produces a concise human report and an unannotated machine-readable dump.

The purpose is operational oversight of one local session: what commands ran, in what working directory, when and for how long, which failed or repeated, how much session time was covered by recorded operations, and which intervals remain unobserved. The tool does **not** claim to audit every action, observe internal model thinking, diagnose provider throttling, or detect uninstrumented MCP calls.

This is the whole coherent capability, **not** a proof of concept to be expanded in later small milestones. Include both storage backends and both reporting audiences now.

## Architecture and invariants

### Independent command-line product

- Add `agenttrace` as an independently executable .NET 11 CLI under the existing `DotNetAiWorkbench.slnx`, with its own product implementation and focused tests. Reuse ordinary .NET libraries or small internal helpers as justified; do not couple it to Autoformat, Hygiene review state, Git checkpoint requirements, Roslyn, or an index service.
- All collection is invoked through the CLI. **No Codex/Claude hooks, OpenTelemetry, MCP server/client implementation, model APIs, agent transcript ingestion, OS-wide command monitoring, daemon, background collector, web UI or hosted analytics.** Codex, Claude Code, and local-model agents can all use the same command instructions when they can execute shell commands. Agent compliance, not agent identity, defines trace coverage.
- Expose discoverable `--help`/`--version` and stable noninteractive commands: `start`, `run`, `begin`, `end`, `mark`, `pause`, `resume`, `stop`, `sessions`, `report` and `export`. Their command/argument semantics below are the required behavior; implementation may choose internal parser/project structure.
- Explicit `--session <id>` ties all post-start operations to one session, avoiding ambient “current session” ambiguity with concurrent chats. `start --name <text>` creates a collision-resistant ID and prints it in a script-friendly form. `sessions` lists available sessions. Human-facing session names are optional metadata, not identities.

### Recorded commands, declared operations and lifecycle

- `agenttrace run --session <id> [--cwd <path>] [--sensitive] -- <executable> [arguments...]` launches the exact specified process and argument vector. Arguments after `--` belong to the child; do not silently interpret them as tracer options, expand them, invoke an implicit shell, or evaluate text as a shell command. Use an **explicit shell executable** (for example, `pwsh -NoProfile -Command ...`) when shell syntax, pipelines, or built-ins are wanted. Default working directory is the caller's current directory; `--cwd` is resolved relative to that directory. The child inherits the caller's environment, stdin and normally visible stdout/stderr; the tracer does not capture or reformat those streams.
- Persist a command-start record **before** launching the child and its completion/exit information afterwards. Observe actual start/end, elapsed duration, executable/arguments or a deliberately redacted representation, working directory, child exit code, and completed/failed/interrupted state. On an ordinarily completed trace, `run` returns the child's original exit code, including nonzero failures. A tracer-specific failure is diagnosed separately and must not be represented as a successful child run. If tracing cannot persist the start, **do not launch** an untraced process.
- `begin --session <id> --kind <kind> --name <text>` returns an event ID, and `end --session <id> --event <id> --status <...>` closes that span. These are **agent-declared**, not independently measured executions; allow an ordinary `external` kind and an explicitly labelled `mcp` kind, so an agent can describe a direct MCP call when it chooses to instrument it. `mark` appends a timestamped note without pretending it has duration. Preserve the provenance difference between wrapped `run` and declared spans in both outputs. Do not claim that missing declared MCP events imply a server was unused.
- `start`/`stop` delimit an explicit chat/session; `pause`/`resume` exclude intentionally acknowledged inactivity (such as waiting for a human) from active-session time. Reject invalid transitions (double-pause, resume without pause, operation on a closed session, unknown session/event); document how to close interrupted sessions with unfinished work without fabricating completion. A forced/incomplete stop may preserve unfinished records but must never invent a successful exit or terminate unrelated processes.
- Every CLI invocation is independent. Session state is durable between invocations, including after the agent process or terminal disappears. Several agents/sessions and concurrent `run` invocations must not corrupt one another or mix event attribution. Command subprocess cancellation should propagate sensibly, avoid silently orphaning a child process tree under normal interruption, and leave truthful incomplete data when abrupt termination prevents completion recording.

### Repository configuration and equivalent local storage

- Resolve a Git worktree/repository root from the invocation context (also permit explicit `--repo <path>` when called outside the tree); descendant directories use the same repository configuration. Configuration is the optional **root** `.agenttrace.json`, independent of `.hygiene/` and `.guide/`. With **no config file**, use JSONL automatically; malformed/unsupported configuration fails visibly rather than silently falling back. Config precedence is explicit: supplied repository path determines which root/config applies, configuration chooses storage, missing config selects defaults. No hidden per-user or agent-vendor configuration is required.
- Version-one configuration is `{"schemaVersion":1,"storage":{"provider":"sqlite","path":".agenttrace/traces.db"}}` or `{"schemaVersion":1,"storage":{"provider":"jsonl","path":".agenttrace/sessions"}}`. The **default** is JSONL in `.agenttrace/sessions/`, one append-only session log per ID; SQLite is one local repository database. Paths are anchored consistently to the repository root and protected against unintended writes outside the configured local destination. The tracer creates its own storage directories, not a Git commit or project checkpoint; generated data under `.agenttrace/` must be Git-ignored without hiding the optional committed config.
- Both providers implement the **same versioned logical session/event schema and observable read/write semantics**. Event IDs, provenance, session lifecycle, UTC timestamps, duration/exit data, partial states and ordering survive either provider. Concurrency must be safe across independent CLI processes (including two writers for one session); JSONL writes must not produce interleaved/torn usable records and SQLite writes must be transactional. A crash after recording start but before completion is observable as unfinished, never erased or inferred successful.
- Switching configuration is **not** an implicit migration of previously written traces. A reader uses the currently selected store and clearly reports missing/unavailable sessions; documentation explains how to retain/read earlier stores. Do not create a cross-store index, synchronization engine, background migration or aggregation service.

### Accurate claims about elapsed time

- For a wrapped process, measure elapsed time with a monotonic clock within the invocation; store UTC start/end timestamps for chronology. Separate measurement from human interpretation. Manually declared cross-invocation spans are calculated from recorded timestamps and labelled accordingly; do not give them the same evidentiary status as a supervised child.
- Reports distinguish **session wall time**, explicitly **paused time**, **covered wrapped-command time** (union of command intervals, not sum when overlapping), **declared operation coverage**, and **unattributed active time**. Exclude pauses and overlapping intervals correctly; when an interval is unfinished or invalid, show its uncertainty rather than manufacturing a completed duration. Include useful largest gaps in the chronological report when grounded in the available lifecycle events.
- “Unattributed” is **not** “model thinking time”. It may include model processing, latency, human waiting, unwrapped commands or uninstrumented MCP activity. The tool makes no vendor-throttling claim and makes no inference that missing events prove no work occurred.

### Outputs, privacy and neighboring contracts

- `report --session <id> [--format text|markdown] [--out <path>]` generates a readable timeline and concise deterministic aggregates: session duration and coverage, commands with durations and statuses, failures/unfinished entries, repeated **identical executable+arguments+working-directory** invocations and total time, and declared MCP/external activity visibly distinguished from verified commands. A text report goes to stdout by default; `--out` writes the requested report. Summaries are descriptive, not subjective “overtesting” verdicts.
- `export --session <id> [--format json|jsonl] [--out <path>]` emits a **complete, deterministic, versioned machine-readable dump** of session metadata, lifecycle records, operation records, provenance, timing and incomplete state, normalized the same way from either backend. No explanatory prose, Markdown fences, model judgments or progress output on the machine-readable stdout; diagnostics go to stderr. `sessions` has usable human and JSON output for discovery. Report/export/read operations must not mutate sessions or execute commands.
- By default do **not** persist child stdout/stderr, environment-variable values, stdin, prompt content, transcripts, or tool-result bodies. Since executable arguments can themselves contain secrets, support `run --sensitive` to persist only a safe executable/placeholder or operator-supplied nonsecret label while forwarding the actual arguments unchanged; make the limitation and local data sensitivity clear. Fail rather than accidentally leak known-sensitive values through “helpful” error dumps. Traces remain local and use a generated, ignored directory by default.
- Existing `dotnet autoformat`, `dotnet hygiene`, solution/project formatting, review/approval lifecycles and their tests/scripts remain unchanged except the additive solution wiring and generic project documentation needed to introduce the independent tool. No clean-Git checkpoint requirement for tracing; it must remain usable while a working tree is dirty.

## Scope and exclusions

**In scope:** complete independent AgentTrace CLI/process boundary, durable session/event model, JSONL and SQLite backends, repository configuration and Git ignore, declared external/MCP spans and markers, concurrency/failure handling, human report, agent data export, help and usage documentation, solution/test project wiring, and focused implementation-level verification.

**Out of scope:** runtime-native integration of any kind (Codex/Claude hooks, MCP or OTel), automatic tool-call discovery, server-side inference metrics, machine-wide capture, dashboards, cloud storage, cross-session analytics, automatic “over-testing” policies, configuration migrations, arbitrary historic importer, NuGet publication, and installed-package qualification. This exclusion does **not** excuse completing the two required local stores or reports.

## Acceptance and material obligations

- **CLI-01 — Standalone CLI surface.** An independent `agenttrace` executable is included in the workbench, with noninteractive discoverable lifecycle/recording/read commands and stable error/exit handling, without loading Autoformat/Hygiene or provider integrations.
- **SES-01 — Session lifecycle and isolation.** Start, explicit session selection, list, pause/resume and stop work durably across invocations; invalid transitions fail, concurrent chat sessions stay distinct, and unfinished operations remain honestly represented.
- **RUN-01 — Accurate wrapped process execution.** `run` launches a direct child with faithful argv/cwd/stdin/stdout/stderr/exit behavior, records start before execution and actual outcome afterwards, and handles process-launch errors and interruption without silent untraced execution or false success.
- **DECL-01 — Manual external activity.** Begin/end and mark operations record optional external/MCP activity with explicit declared provenance, valid IDs and states, without claiming native MCP observation.
- **CFG-01 — Repository setup.** Root/discovery behavior, optional versioned `.agenttrace.json`, exact JSONL default, explicit SQLite selection, path anchoring, bad-config diagnostics, and generated-data Git exclusion are implemented.
- **STORE-01 — Durable interchangeable providers.** JSONL and SQLite preserve equivalent canonical logical data, including concurrent writers, unfinished events and valid session state after interrupted writers.
- **TIME-01 — Truthful timing.** Monotonic wrapped-command duration, UTC chronology, concurrency-aware interval coverage, pause exclusion, and explicitly unattributed/non-thinking intervals are computed and labelled consistently for both providers.
- **REPORT-01 — Human report.** `report` produces usable console and file text/Markdown reports with chronological events, duration summaries, failed/unfinished activity, repeated commands and declared-operation distinctions.
- **EXPORT-01 — Agent data dump.** `export` emits complete versioned JSON/JSONL without non-data stdout, with equivalent content across storage modes; session discovery is available in machine-readable form.
- **SAFE-01 — Local/privacy semantics.** No process-output/environment capture by default, explicit sensitive-argument suppression, scoped local writes, no data loss through false completion, and no interference with existing workbench operations.
- **TEST-01 — Focused behavioral coverage.** Deterministic model/backend tests and representative real-process CLI fixtures establish the material execution, storage, concurrency and reporting invariants without a full installed-consumer or model-agent test suite.
- **DOC-01 — Operative documentation.** Update `README.md`, `docs/ARCHITECTURE.md`, `docs/ENGINEERING.md`, suitable CLI help/usage/config examples, `docs/MILESTONES.md` and this milestone/ledger completion note to explain actual usage, independent tool boundaries, optional MCP declarations, timing limitations and deferred release work.

No persistent SDK installation, CI change or remote-service provisioning is authorized. If a material toolchain prerequisite is missing, report the actual blocker rather than silently substituting an unrepresentative environment.

**During implementation:** focused tests for event model, interval union/pause arithmetic, configuration discovery/invalid inputs, persistence parity, duplicate/unknown IDs and cancellation state; compile affected new projects. Use small disposable fixtures and short-lived commands instead of the root aggregate validation stack.

**At milestone completion:** on the actual Windows/.NET process boundary, exercise a small set of high-information scenarios covering (a) a short successful child with redirected streams/working-directory/arguments, plus an intentional nonzero exit; (b) a concurrent pair of sessions/commands with overlapping intervals and a declared MCP span; (c) the same session exercised against JSONL and SQLite to compare normalized export/report semantics; and (d) a failed launch or interrupted command leaving an honest incomplete/failed record. Include a config-absent JSONL case, an invalid config rejection, and sensitive-command redaction in these or focused tests. Run focused target tests once after relevant final changes. No live model calls, real MCP server or real multi-hour milestone is required to validate a deterministic CLI.

**Important risks to discriminate:** failure to forward argv/pipelines exactly, a wrapper reporting success when the child failed or trace persistence broke, untraced execution after failed start write, orphaned or falsely completed work on cancellation, mixed session IDs under concurrency, JSONL record corruption, SQLite/JSONL diverging exports, negative/double-counted non-command time, paused hours mislabelled as thinking, or secrets copied from process streams/arguments. The above checks and targeted source review should cover these without one test per obligation.

**Deferred to release:** packaging/tool manifest and installed `agenttrace` consumer invocation, final-distribution startup/help, broader platform compatibility (only Windows 11 is currently documented), consumer-repository trials and routine workbench aggregate release checks. Do not run existing Autoformat/Hygiene installed-consumer validators merely because AgentTrace joins the solution.
